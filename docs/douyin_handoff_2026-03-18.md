## 4. 已经稳定/已确认正确的部分

### 4.1 本地采集模式

当前本地模式已经改成：

1. 用户在宿主 App 里点 `开始抖音采集`
2. 宿主进入待命
3. 用户手动打开抖音
4. 无障碍服务继续接管

这点很重要：
- 本地模式不要主动拉起抖音
- 这是为了让动作更自然，减少额外风险

### 4.2 抖音前半段路径

人工和自动都已经反复确认过，以下路径是对的：

1. 打开抖音
2. 进入 `团购`
3. 打开搜索输入页
4. 输入 `郑州美莱`
5. 到达商家结果页

### 4.3 团购首页存在两种 UI

不要再假设只有一种。

已确认的两种：

1. 旧样式
- 页面上方直接出现红框搜索条
- 左侧城市，如 `郑州`
- 中间可能显示 `美莱团购`
- 右侧有 `搜索`

2. 新样式
- 顶部 `团购` tab 已选中
- 右上角有单独 `搜索` 按钮

这两种都已经在代码里做过兼容。

### 4.4 店铺首页的强判定

只有同时出现下面 2 个区域，才算真正进入店铺首页：

1. 上方商家信息区
- 商家名：`郑州美莱医疗美容医院`
- `关注`
- 以及同区的店铺信息，如：
  - `回头客1千+`
  - `无隐形消费`
  - `详情`
  - `在线咨询`
  - `电话`

2. 底部固定操作栏
- `医疗美容`
- `订单`
- `预约有礼`
- `在线咨询`

这套规则已经是当前最可靠的“进店成功”标准。

## 6. 这几天反复失败的共同根因

这是最重要的一段，后续接手的人一定要先看。

### 6.1 过去一直在“猜页面 + 立刻执行”

之前的主要问题不是某一个坐标错，而是：

- `SearchController.kt` 同时承担了：
  - 页面识别
  - 动作执行
  - 动作结果判断
- 一旦页面样式有分支，就会：
  - 还没确认当前页是什么
  - 就已经开始点下一步

这会导致：
- 已经在团购页，又重复点团购
- 已经进店，又以为没进
- 已经偏到错误区域，还继续重放首页动作

### 6.2 搜索结果页里有多个“郑州美莱医疗美容医院”

这是当前最关键的真实问题。

在抖音商家结果页里，页面上可能同时出现：
- 上半屏的店铺入口带
- 下方团购卡中的医院署名
- 其它与商品、问答、推荐相关的上下文

之前代码的问题是：
- 只要文案匹配到 `郑州美莱医疗美容医院`
- 就可能被当成“店铺入口候选”

结果就是：
- 实际点击到了下方商品区
- 不是点到你确认过的店铺入口带

### 6.3 取证方法也会制造误判

之前有一段时间是并行抓：
- 截图
- XML
- 窗口信息

这在抖音快速切页时会出问题：
- 截图可能还是抖音页
- XML 可能已经切回宿主 App
- 然后人会误以为“代码又做了奇怪跳转”

所以后续必须串行取证。
