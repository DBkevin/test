## 3. 今天确认掉的旧问题

### 3.1 左侧抽屉不是当前主问题

前面出现左侧抽屉的主要原因，是团购页搜索前预处理曾经对可滚动节点直接做过 accessibility scroll。

今天已经确认的稳定做法是：

- 团购页预处理滚动只能使用屏幕中轴竖向手势
- 不再对抖音首页/团购页的顶层 scrollable 节点直接做无障碍滚动

这条结论已经写进 runbook，应视为固定纪律。

### 3.2 团购页内搜索入口已经定位到真实节点

今天抓到的稳定事实是：

- 当前样式的团购页内关键词入口真实 view-id 是：
  - `com.ss.android.ugc.aweme:id/et_search_kw`

后续应优先按这个真实节点处理，而不是继续猜固定样本点。

## 4. 今天发现的两个真正问题

### 4.1 问题一：进入抖音后有时会重复点 `团购`

tap trace 证明代码确实又点了一次 `团购`，不是用户错觉。

根因不是“动作乱跑”，而是：

- 状态机之前只接受严格 `GROUPBUY_HOME`
- 对“已经可继续但还没被严格分类成 `GROUPBUY_HOME` 的团购态”识别太窄

今天得出的稳定抽象是：

- 如果页面已经满足：
  - `团购` 已选中
  - 团购页内搜索入口存在
  - 没有商家结果页结构
  - 没有店铺底部固定浮窗
- 那它就应该被视为“可继续的团购态”
- 这种状态下不能再重复点 `团购`

### 4.2 问题二：商家结果页明明到了，却一直判失败

今天两次关键日志都走到了：

1. 打开团购页内搜索入口
2. 进入专用搜索输入页
3. 输入 `郑州美莱`
4. 点击提交
5. 最终报：
   - `Douyin merchant result page not confirmed after search submit`

但截图已经证明商家结果页真实存在。

根因判断：

- 旧结果页确认逻辑过度依赖：
  - 当前 activity 名
  - 商家标题落在固定高度带
- 当前抖音结果页里，首个商家入口已经更靠上，固定高度带太窄

后续稳定确认口径应该是组合信号，而不是单一信号：

1. 顶部结果页 tab：`团购 / 直播 / 视频`
2. 搜索词仍是目标词
3. 页面里存在目标商家节点
4. 商家节点上下文包含 `评价` / `回头客` / `人均` / 距离等结果页结构
