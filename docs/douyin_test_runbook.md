# 抖音自动采集测试 Runbook

## 目标

把“已经验证过的方法”固定下来，后续所有真机验证都按这份 runbook 走，不再靠临场摸索。

## 一、当前稳定的基线路径

已验证正确的前半段路径：

1. 在 `com.example.a11yframework` 主界面点击 `开始抖音采集`
2. 手动冷启动抖音
3. 如果当前还不在 `团购`，自动切到顶部 `团购`
4. 如果当前已经在 `团购`，不要重复点 `团购`
5. 进入 `团购` 页后，先上下滑几次，再回到最上面
6. 在团购首页顶部等待 `10~20s`，让直播提醒自行消失
7. 只从团购页内搜索入口进入搜索输入页
8. 清空搜索框，输入 `郑州美莱`，自动触发搜索或点击 `搜索`
9. 自动进入商家结果页
10. 自动点击 `郑州美莱医疗美容医院` 卡片上半部分，进入店铺首页

补充口径：

- 必须先走 `团购`，不能直接走默认搜索链路。
- 原因：默认搜索容易触发 AI 详情干扰，插入额外内容，破坏结果页判定。
- 当前目标是先跑通抖音专用链路：团购专用入口、专用搜索输入页、专用提交按钮；先不复用通用搜索器启发式。
- 当前代码纪律也要和 runbook 一致：`首页 -> 团购 -> 团购页内搜索入口 -> 专用搜索输入页 -> 专用提交 -> 结果页` 这几步必须逐步确认，任一步未确认都直接失败，不再继续猜测或回落到通用搜索。
- 默认“推荐已选中”的首页视频流，只要底部主栏仍在、顶部搜索仍在，就属于合法 `HOME_FEED`；不能把它当成中间页连续 `Back`。
- 进入 `团购` 后不要立刻点搜索入口；顶部搜索区如果被直播提醒遮住，先做预处理滚动并等待其自然消失。
- 即使页面右上角出现单独 `搜索` 按钮，也不要点它；当前稳定路径只允许点击团购页内搜索入口。
- 如果意外进入天气/综合搜索页，或 `Back` 后出现左侧抽屉，先继续 `Back` 退回稳定首页/团购页；抽屉未关闭前禁止继续点底部 tab。

## 二、当前固定点击区域

默认规则：优先使用“区域点击”，单点坐标只作为当前机型的样本，不作为唯一规则。

- 首页顶部 `团购`
  - 纪律：优先点击当前页面真实 `团购` tab 节点的 bounds，不再盲点右侧旧样本区域
  - 旧样本点 `1050,220` 只代表早期样式，不再作为当前默认 fallback
- 团购页搜索入口
  - 旧样式建议区域：`x=80..500, y=320..420`
  - 旧样式样本点：`290,370`
  - 当前样式建议区域：`x=220..930, y=300..440`
  - 当前样式样本点：`383,373`
- 纪律：只点搜索条里的“关键词容器实际 bounds”，不走节点点击，不再依赖固定样本点；不要点条内右侧 `搜索`，更不要点页面右上角单独 `搜索`
- 失败纪律：点完搜索入口后，如果没有进入抖音专用搜索输入页，就直接判失败并退出当前链路，不要继续点别的入口
- 结果页店铺入口带
  - 建议区域：`x=263..1384, y=487..708`
  - 说明：只点首个商家卡上半部分，不点下方统计行，不点团购卡
- 店铺页 `展开更多`
  - 规则：用底部固定浮窗做锚点，优先点“最后一张团购卡”下方的空白带
  - 当前机型样本：
    - 底部浮窗顶部约 `y=2954`
    - 成功样本点：`720,1200`
    - 对应到底部浮窗顶部偏移约 `1750px`
- 店铺页 `展开全部`
  - 规则：继续使用底部固定浮窗做锚点，点击团购卡片尾部后的下一条空白带
  - 当前机型样本：
    - 底部浮窗顶部约 `y=2954`
    - 成功样本点：`720,1340`
    - `720,1090` / `720,1240` 已验证会误进商品详情，禁止继续当基线

## 三、团购首页的两种已确认样式

### 1. 旧样式：红框搜索条

- 特征：
  - 页面上方直接出现搜索条
  - 左侧有城市，如 `郑州`
  - 中间可能出现 `美莱团购`
  - 右侧有 `搜索`
- 处理：
  - 直接点击搜索条中间区域，进入搜索输入页

### 2. 当前样式：tab 行 + 团购页内搜索条 + 右上角单独搜索按钮

- 特征：
  - 顶部 tab 区出现 `已选中，团购，按钮`
  - tab 行下方还有一条团购页内搜索条，左侧是城市，中间是关键词，右侧是条内 `搜索`
  - 顶部右上角有单独 `搜索` 按钮
  - 页面底部仍有抖音主底栏 `首页 / 朋友 / 消息 / 我`
- 已验证素材：
  - `D:\project\adb\artifacts\groupbuy_current_c0e68dd.xml`
  - `D:\project\adb\artifacts\groupbuy_current_c0e68dd.png`
- 当前 ADB 基线：
  - 城市区：`[77,342][181,403]`
  - 关键词区：`[278,347][488,399]`
  - 条内 `搜索`：`[943,324][1125,422]`
- 处理：
  - 先做团购页预处理：向下滑几次，再回到顶部，等待直播提醒自然消失
  - 只允许点击团购页搜索条里的“关键词区”，进入搜索输入页
  - 不允许点击搜索条右侧 `搜索`
  - 不允许点击右上角单独 `搜索`
  - 右上角 `搜索` 当前视为无效路径，会引入不可预测页面，不再作为 runbook 的有效分支
  - 如果“团购已选中”但页面仍未被识别成团购首页，不能继续试搜索入口，要先停在这一层排查页面识别

### 3. 团购页直播提醒处理

- 现象：
  - 进入团购页后，顶部搜索入口有时会被直播提醒遮住
- 处理纪律：
  - 不要在刚进团购页时立刻点搜索
  - 先向下滑几次，再向上滑回顶部
  - 这里的预处理滚动只能使用屏幕中轴的竖向手势，不允许对“第一个可滚动节点”直接做无障碍滚动
  - 原因：抖音首页/团购页经常把顶层 `viewpager` 暴露成 scrollable；对它做 accessibility scroll 可能会拉出左侧抽屉或切到横向容器
  - 回到顶部后等待 `10~20s`
  - 直播提醒自行消失后，再继续点击搜索入口
- 目的：
  - 避免把搜索入口点击失败误判成“未进入团购页”或“搜索入口不存在”

## 四、当前固定页面锚点

### 1. 进入店铺首页的判定

同时满足这 2 个区域才算真正进入店铺首页：

- 上方商家信息区
  - `郑州美莱医疗美容医院`
  - `关注`
  - `回头客1千+ / 无隐形消费 / 详情 / 在线咨询 / 电话` 等店铺信息
- 底部固定操作栏
  - `医疗美容`
  - `订单`
  - `预约有礼`
  - `在线咨询`

### 1.1 店铺页弹窗纪律

- 如果进入店铺页后出现优惠券弹窗，一律优先点击关闭。
- 不要在弹窗遮挡状态下继续点团购卡或滚动页面。

### 2. 团购列表结束的判定

以下任一稳定条件成立时，都要停止继续把页面当团购主列表采集：

- 团购区域下方出现 `收起`
- 以底部固定浮窗为锚点，识别到“尾部收起带”
  - 当前机型样本里，底部浮窗顶部约 `y=2954`
  - `收起` 对应的空白带中心大约位于“底部浮窗顶部上方 `760~1260px`”这段区域
- 已经进入非团购内容流，例如 `预约到店专属礼`、`用户评价`、`你可能感兴趣的地点`

补充展开规则：

- 店铺首页默认通常只展示 `4~6` 个团购。
- 先点击 `展开更多`，会继续露出一部分团购，数量不固定。
- 再往下可能出现 `展开全部`，点击后要把剩余团购全部展开。
- 只有到达 `收起` 或尾部收起带，才算真正到头。
- 每次下滑后先判定是否出现 `展开更多` / `展开全部`，再决定是否继续滑动。
- `展开更多` / `展开全部` 当前在 XML 中可能是无文案空节点带，不能只靠 `text=` 匹配。
- 当前更稳的做法是：
  - 先识别底部固定浮窗
  - 再识别“最后一张团购卡”下方的空白动作带
  - 用动作带相对底部浮窗的偏移，区分“展开带”和“收起带”

### 3. 错误区域判定

一旦出现这些推荐/兴趣模块，就说明已经滚偏，不能继续把它当成团购主列表：

- `你可能感兴趣`
- `你可能感兴趣的地点`
- `猜你喜欢`
- `服务 / 评价 / 推荐` 下的非团购内容流

## 五、每轮测试的执行顺序

1. 先看当前 APK 是否是最新云编译产物
2. 只要换成新的 APK，一律先走固定安装流程，不走覆盖安装捷径：
   - `adb uninstall com.example.a11yframework`
   - `adb install <latest-ci-apk>`
   - `adb shell settings --user 0 put secure enabled_accessibility_services com.example.a11yframework/com.example.a11yframework.core.FrameworkAccessibilityService`
   - `adb shell settings --user 0 put secure accessibility_enabled 1`
3. 安装后立刻回读确认无障碍服务状态：
   - `adb shell settings --user 0 get secure enabled_accessibility_services`
   - `adb shell settings --user 0 get secure accessibility_enabled`
   - 必要时再看 `adb shell dumpsys accessibility`
4. 第 1 轮必须从抖音冷启动开始跑
5. 第 1 轮结束后，再强制冷启动抖音，完整跑第 2 轮
6. 每一轮都要单独保留点击轨迹，不能只留最终截图
7. 先看当前页面是否符合 runbook 的前置页面
8. 只在前置页面成立时才执行固定点位
9. 每次路径跑通后，先留一张截图和一份 XML
10. 如果路径跑偏，先记录“从哪一步开始偏”，不要继续在错误页面上补点位

补充纪律：

- “新的 APK”默认都要先卸载旧包再安装，避免签名不一致和旧状态残留。
- 不要假设安装新包后无障碍服务会自动恢复；每次都由 ADB 显式拉起并验证。
- 如果设备对 ADB 安装弹 `INSTALL_FAILED_USER_RESTRICTED`，先处理系统安装校验，再继续本轮验证。

### 5.1 新列表页/新边界的处理方法

只要要新增列表采集、补页面边界、补点击区域、补停止条件，都先走一轮“真机人工辅助确认”：

1. 先手动把流程走通，确认正确页面和正确边界
2. 每个关键节点都留截图
3. 对稳定页面补抓 XML
4. 先从截图确认视觉边界，再用 XML 辅助确认 bounds
5. 先形成点击区域、展开顺序、停止条件，再回到代码实现

禁止反过来做：

- 不要先写代码，再靠连续试错去猜页面边界
- 不要把一次偶然成功的单点坐标直接当成长期规则
- 不要在未确认正确页面前继续滚动或继续点击

## 六、每轮测试必须沉淀的内容

每次真机测试结束后，至少补 1 项到文档里：

- 一份完整的点击轨迹
- 一个新的稳定点位
- 一个新的页面识别锚点
- 一个新的错误轨迹分析
- 一份新的“正确页面”截图/XML 基准资产

## 七、点击轨迹要求

- 关键点击至少要记录：
  - 开始抖音采集
  - 首页 `团购`
  - 团购页搜索入口
  - 搜索页 `搜索`
  - 结果页开店点击
  - 后续所有 `展开更多`
- 新版宿主会把点击轨迹写到应用私有文件：
  - `/data/user/0/com.example.a11yframework/files/tap-trace-latest.txt`
- 每次双轮测试后，都要把这份轨迹和截图/XML 一起看，不只看最终停留页

## 八、结果页开店纪律

- 结果页只允许点击“店铺入口带”，不允许把下方团购卡、问答卡、医院文案、点评文案当店铺入口。
- 结果页点击目标是“卡片上半部分”，不能点商品卡，否则会进入商品详情。
- 如果同一页出现多个 `郑州美莱医疗美容医院`，优先选：
  - 位于结果页上半屏
  - 父级是一整条横向入口带
  - 上方没有团购商品标题
- 明确排除：
  - 团购卡里的医院署名
  - `继续追问`
  - `已售 / 人逛过 / 券后 / 次卡` 这类商品上下文

## 九、取证纪律

- 截图、XML、窗口信息不要并行抓。
- 原因：
  - 抖音页面切换很快，并行取证会把两个时刻混在一起，造成“截图是抖音，XML 却是宿主 App”这种假象。
- 正确顺序：
  1. 先截图
  2. 再抓 XML
  3. 再抓窗口/日志
  4. 最后拉点击轨迹

## 十、代码同步与临时文件纪律

- 只要为了真机链路改了代码、规则或 runbook，就在本轮结束后立刻提交并推送到 GitHub。
- 不要长时间保留大量未提交改动，避免本地与远端偏离后让桌面端界面变卡。
- 真机排查时拉下来的截图、XML、日志、CI APK 默认都当临时文件处理。
- 无用的临时抓取在分析结束后直接删除，不要继续堆在 `artifacts/`。
- 只有明确要长期复用的“基线样本”才允许保留，并且需要在 runbook 里说明用途。
- 临时抓取默认依赖 `.gitignore` 阻止追踪；如果某份样本确实值得沉淀，再手动加入版本库。

## 十一、当前最重要的纪律

- 不在错误页面上重放首页坐标
- 不在首屏未稳定时抢先下滑
- 不把店铺尾部页误判成离开店铺
- 所有新成功方法都必须写回文档
